V1 Agent Field Report

2026-11-19 · 42 eval questions · 2 models (gpt-oss-120b, qwen3.8-27b) · plain model vs full agent · sandbox and verifier attack tests · market and eval-method research

The framework does what it was built for on a weaker model: more right answers, no dead citations, and confidence you can sort by. It does not yet prove the V1 claim, because the eval is too small, rate limits erased a third of the runs, and the strongest model already gets the easy questions right on its own.

Verdict

What works. Across every full-agent run, 0 cited links were dead (plain model: 11% on gpt-oss-120b, 20% on qwen). On the weaker qwen model the agent lifted accuracy (dev 65% → 87%, hard 33% → 44%) and cut calibration error (dev 0.34 → 0.13, hard 0.64 → 0.24). On the hard set, the agent's most-confident half was 80% right, versus 38% for the plain model.

What doesn't yet. No difference is statistically significant (paired McNemar p ≥ 0.25) because only 8–16 questions per comparison survived rate limits. Weak-model code fails often, and one failure path produced a false statement ("the file was not provided"). Research answers are thin: rubric scores 0.42–0.62.

Five things to do next, in order: (1) a tested statistics library inside the sandbox, (2) a deterministic data audit for attached files, (3) honest failure messages when analysis fails, (4) a rate-limit-aware scheduler, (5) grow the eval to 150+ questions with generated (unmemorisable) maths variants and a claim-level citation-faithfulness metric.

What was tested

  • Dev set (26 questions, starter): 6 factual, 10 classic probability, 3 research, 4 abstain or false premise, 3 rule-trigger.
  • Hard set (16 questions, new): probability problems with unfamiliar numbers, statistics on attached data files (including one with a planted prompt injection), one fact, and abstain items. This is the held-out test set, so its questions are not published.
  • Systems: plain = one call to the model asking for answer, confidence and citations; full = the agent. Same pinned model for both, no fallback.
  • Attack tests: 8 sandbox escape attempts, verifier gaming by code review, prompt injection through a data file.
  • Research: two Haiku agents surveyed 15 research products and the eval literature; I re-checked the key studies against their abstracts.

Every answer key was computed in Python, not recalled. All results files are in agent/evals/results/; agent report <files> reproduces every number below.

How to read this

  • The model matters more than the framework when the model is strong. gpt-oss-120b on its own gets classic and novel probability right, so the agent adds nothing to accuracy there; it only improves calibration and removes dead links.
  • The framework matters when the model is weak. Plain qwen was wrong on 8 of 10 hard maths items at 95–100% stated confidence (it answered the gambler's-ruin question with a string of zeros at confidence 1.0). The agent's direction is consistent across every comparison: it never lost a question the plain model got right, and won 6.
  • Confidence became usable. "Most-confident half" is the accuracy of the answers the system was surest about. For the agent it is 80–100% everywhere, so sorting by confidence tells you what to check first. For plain qwen on the hard set it is 38%: its confidence carries no information.
  • The cost is real. 10–25× the tokens and 10–70× the time (30–70 s per question). On Groq's free tier that is roughly 20–40 full-agent questions per model per day.
  • Errors are mostly rate limits (24 of 37), the rest Groq rejecting malformed JSON from qwen. Errors are excluded from accuracy, which is why "graded" varies.

What the framework caught

  • A wrong number from bad code. The first base-rate run computed int((1-0.90)*1000) = 99, giving 0.1638 instead of 0.1624. The simulation was too noisy to notice. Fix: cross-checks must now be precise to 0.25% of the value, agreement is within 3 standard errors, and exact inputs must be built from decimal strings.
  • Unsupported numbers. On the hard set, 5 of 9 graded answers had first-draft claims that failed verification (numbers not in any computation output); they were fixed or relabelled speculation, and the answer's confidence dropped to 0.19 instead of asserting a wrong value.
  • False premises. Every graded abstain item was flagged correctly, including the invented 2019 Nature study (the plain model also caught that one).
  • Overreach in the headline. The answer check rewrites a direct answer that is stronger than its verified claims.

Where the market is, and where V1 fits

Surveyed: OpenAI, Gemini, Perplexity and Claude research modes; Elicit, Consensus, scite, Undermind; OpenScholar, PaperQA2, STORM, GPT Researcher, Local Deep Research; ChatGPT data analysis and Julius for statistics.

Documented gaps across the market

  • Citations that exist but don't support the claim. Frontier deep-research models keep links working more than 94% of the time but are factually right about the cited content only 39–77% of the time, and accuracy falls about 42% as tool calls grow from 2 to 150 (Onweller et al., 2026). Citation accuracy across deep-research systems ranges 40–80%, with large shares of statements unsupported by their own sources (DeepTRACE, 2025). Earlier: 51.5% of sentences fully supported in generative search engines (Liu et al., 2023).
  • No calibrated confidence. OpenAI's own launch post says Deep Research is weak at confidence calibration (OpenAI). The only per-claim confidence found in any product is scite's citation-label confidence (scite).
  • Weak, unverified statistics. Code-running tools show the code but don't check it. In a 2026 study of an LLM agent analysing a clinical dataset, 8 of 17 summaries were fully satisfactory and 2 had clinically meaningful errors (PMC study).
  • Abstention is rare. Only PaperQA2 documents answering "insufficient information" (21.9% of LitQA2 answers) (PaperQA2).
  • Fabricated references in un-grounded models. GPT-4o fabricated 78–90% of citations on recent-literature prompts in Ai2's benchmark (OpenScholar, Nature).
V1 is ahead on
  • Claim-level faithfulness: every sourced claim's quote is checked verbatim, then judged by a checker that sees only claim and passage. This targets the market's main documented gap directly.
  • Numbers backed by executed code, with exact-vs-simulation cross-checks.
  • Per-claim evidence tags and a confidence that ranks answers.
  • Bayesian updates and study pooling computed in code, not by the model.
V1 is behind on
  • Retrieval breadth: three free APIs and abstracts, against products reading dozens to hundreds of full sources.
  • Report writing: short claim lists, not structured multi-section reports.
  • Speed, connectors (files, Drive, MCP), full-text PDFs and UI.
  • Scale of evaluation: no published numbers on a public benchmark.

Positioning that follows from this: don't compete on breadth. Compete on "every number and quote is checked", for quantitative and statistical questions, where the market is weakest and V1 is already strongest. Measure it the way the 2026 paper does (claim-by-claim against the fetched source) so the claim is comparable.

The eval harness

What it does now

  • Plain vs full on a pinned model; graders: string match, numeric tolerance (fractions, percentages, inputs excluded), model-graded rubric and abstention, rule loading from the trace.
  • Metrics: accuracy with 95% Wilson intervals, most-confident-half accuracy, expected calibration error, Brier score, dead-citation rate, errors kept apart from wrong answers, tokens and time.
  • Paired comparison with an exact McNemar test; resumable runs; re-run by id.

Framework choice: the Rust harness is enough. Inspect AI or promptfoo are worth adopting only for their ready-made datasets and red-team suites, not to replace the runner.
